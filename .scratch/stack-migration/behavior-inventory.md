## Authentication and profile

QAS verifies Cloudflare Access assertion cryptographically (RS256, issuer, audience, exp/nbf, Access application type), normalizes verified email, resolves invited active identity; local cookie never bypasses QAS. JWKS unknown-key refresh covered by `web/tests/auth/access.integration.test.ts`. Sources: `web/src/server/auth/access-jwt.ts`, `identity.ts`, `db/transaction.ts`.

Local single email-or-Thai-mobile field normalizes lowercase email or domestic `0[689]...` / international `+66[689]...` (spaces/hyphens accepted). Unknown identifier creates User once under canonical-identifier advisory lock; linked identifier reuses User; historical unlinked identifier stays reserved. Random 32-byte token is sent only in `deledger_local_session`, 7-day Max-Age, HttpOnly, SameSite=Lax, Path=/; SHA-256 digest stored. Expiry/revocation/archive checked server-side. Sources: `web/src/server/auth/local.ts`, services/local-auth.ts; migration 202609050001.

Profile owner binding cannot be caller-chosen; current email and phone unique, historical identities reserved, at least one login contact required. Optional birthday is real ISO date and not future Bangkok day; null clears it. QAS can change birthday but not contact fields. Local User switching isolates profile/finance. Source: services/profile.ts and migration 202609050001. Tests: `web/tests/auth/local-auth.unit.test.ts`, `local-auth.integration.test.ts`, `identity.integration.test.ts`, `config-environment.unit.test.ts`; E2E `web/e2e/local-auth-profile.spec.ts` covers visible forms and session-expiry clearing.

## Complete database ownership inventory

Schema migrations currently belong to node-pg-migrate, not Prisma. There are **nine application tables** after local identity migrations: app_user (plus date_of_birth), user_identity_email, user_archive_period, reporting_month, balance_snapshot, monthly_recurring_expense, monthly_expense_detail, user_identity_phone, local_session. Migration tracking and pg_cron are additional infrastructure objects. Sources: `db/migrations/202608310002_schema.cjs`, `202609050001_local_identity.cjs`, `202609050002_local_identity_constraints.cjs`.

Important constraints: owner/month compound keys and owner/month/setup compound foreign keys; RESTRICT financial deletion; one active email/phone per User; historical globally reserved contact primary keys; one unclosed archive period; first-of-month and tracked interval checks; supplied/prior-ending opening-source invariant; paired closedAt/closedBy; nonnegative revision and money; setup name/kind/fixed-amount relation; positive unique month position **DEFERRABLE INITIALLY DEFERRED**; one detail per setup/month; session digest and expiry checks. Snapshot interval/open status and most lifecycle rules are service checks, not triggers. No application `CREATE TRIGGER` found in migrations. Preserve invariant behavior with Prisma schema plus explained PostgreSQL-only constraints where needed; do not mistake absence of Prisma DSL syntax for permission to drop constraints.

RLS is ENABLED and FORCED on all nine tables. Owner setting is transaction-local `deledger.user_id`; missing context sees no owned rows. App User policy uses id, others owner_id. Runtime role deledger_web is nonprivileged with deliberately narrow grants: app User SELECT/UPDATE; months SELECT/INSERT/UPDATE; snapshots SELECT/INSERT; setup SELECT/INSERT/UPDATE; details SELECT/INSERT/DELETE; identity/archive read grants added later. Privileged SECURITY DEFINER functions mediate identity and operator actions with fixed `pg_catalog, public` search path and PUBLIC execute revoked. Migrations/role bootstrapping: `db/migrations/202608310003_rls.cjs`, migrations 004/006/007/local_identity, `db/init/001_roles.sh`. Tests: `web/tests/database/rls.integration.test.ts`, persistence, identity. Nest service ownership must include replacing privileged database identity entry points without granting ordinary user requests arbitrary owner access.

## Discrepancies and concrete parity gaps

1. **Multi-month catch-up:** migration 004 closes existing overdue rows before inserting all absent months, but newly inserted past months have no close facts. One invocation after several months of downtime can leave several open rows until another invocation. Existing catch-up test covers adjacent month. Recommendation: decision/spec should require a single completed catch-up to leave historical generated months automatically closed and current month open; document this as a correction, not claim existing implementation already does it.
2. **Closed detail operations:** domain allowedActions says confirmDetails false for closed month, but HTTP PUT sets replace:true; service allows closed confirmation even when no prior detail exists. Cancellation also works closed. Preserve actual API capability unless explicitly settled otherwise; add route-level closed fixed/variable/cancel cases. ADR 0001 generally supports correction; don't impose open-only service rules merely because UI hides actions.
3. **Downstream semantics:** actual dependency is immediate prior Ending Balance, not recursive spending propagation. Missing A Ending Balance prevents B Starting Balance; C can calculate from B Ending Balance if independently supplied. `affectedMonthKeys` simply lists next calendar row, even when its opening source is supplied. Record exact accepted semantics before broadening invalidation metadata.
4. **Profile contact replacement:** migration local_identity inserts replacement contact before unlinking prior contact, while active-owner uniqueness is immediate. Replacing one existing nonnull email/phone with a new one may hit its own owner uniqueness constraint; tests cover linking missing contact and cross-owner races, not same-kind replacement. Add regression and deliberately correct ordering in Nest transaction.
5. **Recovery/export inventory stale:** operator_export includes owner (thus birthday), emails, archives and financial tables but omits phones and local sessions. Restore verification checks original seven tables, not nine. Recommend phone export and all-table restore verification; decide whether auth session secrets/digests belong in user export (no need to invent them into export). Physical backup includes database tables regardless of stale verification list.
6. **Readiness is old-topology-specific:** requires node-pg-migrate row and pg_cron job and is authenticated. Nest migration/scheduler ownership requires an equivalent readiness implementation; retaining these exact queries would falsely fail a healthy new system. Operational backup-mode behavior should remain.
7. **Clock testing differs from production SQL:** dirty test helper replaces current_business_date plus both catch-up wrapper functions so tests use frozen date, then restores them. Production wrappers independently read wall clock. Preserve deterministic tests through one business clock seam; do not port SQL function rewriting into Prisma tests.
8. **Concurrency/rollback evidence incomplete:** existing monthly stale-write tests are mostly sequential. Add two concurrent writes with same revision (exactly one success), reorder+confirm race, archive+request race, two simultaneous catch-ups, login/profile claim race, and induced exception after first mutation proving no partial detail/setup/revision writes.
9. **Precision/ordering coverage:** add largest legal amounts, 0.01 sums, null-vs-zero, sums above input precision, negative derived totals, same-day snapshot tie order, revision beyond JS safe integer. Preserve strings for revision and money at JSON boundary.
10. **History pagination:** current implementation filters/limits months but appends all completed crossing gaps on every page; repeated gaps are existing API behavior. Do not silently redesign pagination while migrating.

## Recommended validation seams

Use public HTTP against a real Nest process + isolated PostgreSQL for auth, envelopes, RLS owner binding, revision concurrency and full month/lifecycle journeys. Unit-test pure money/calendar/reconciliation and projections with exact strings. Service integration should use Prisma transaction with controllable clock and simulate concurrent operator/scheduler work. Keep UI component/E2E contracts unchanged, then run at least one unmocked local login→onboard→snapshot→setup/detail→close/correct→history/profile path. Validate clean Prisma migration from an empty verified Deledger test DB and a second idempotent deploy; inspect constraints/RLS/least privilege directly. Render and exercise both local and private Compose topology; run a real isolated backup/restore smoke test after changing migration/schema/scheduler ownership.
